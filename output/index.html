Order to delivery, in four steps

1 · Order intake

Orders land from the Costco portal (Colladium), Shopify stores and Amazon, and are checked for quantity, stock and address problems.

2 · Processing

Orders are registered and pushed in Cin7. This repetitive push step is the one the Python automation took over (see tab 4).

3 · Warehouse & 3PL

Released orders flow to CartonCloud for picking and dispatch from the Sydney, Melbourne or Brisbane warehouse.

4 · Tracking & delivery

Consignments are tracked through EWE, AusPost and DHL until delivery; exceptions come back as inquiries (see tab 5).

Systems used across the flow

Colladium — Costco B2B portal Shopify — Segway AU & Roborock stores Amazon — Hohem & 360 orders Cin7 — order management CartonCloud — warehouse / WMS EWE — freight tracking AusPost Merchant Portal DHL Google Sheets — inquiries, returns, freight trackers SharePoint / OneDrive — stock on hand & incoming stock

Takeaway: No single system runs this operation — the skill is keeping ten of them in agreement on every order.

Cin7 Order Push

The Cin7 order-push flow for the Shopify Roborock-Store channel — the automation from tab 3, shown step by step.

Takeaway: The automation is conservative by design: it cleans, filters and checks first, pushes second, and stops the whole round if any stage fails.

Channel

Shopify

Roborock-Store channel.

Trigger

Cin7 login

A round starts from a signed-in Cin7 session.

Rounds

~2 per day

Order-push rounds run about twice a day.

The seven stages

Stage 1 — Cleanse

Incoming orders are cleaned first: duplicates, malformed lines and obvious errors are removed before anything else happens, so later stages only ever see valid orders.

Stage 2 — Filter, branch to Head Office

Orders are filtered to the Roborock-Store channel and branched to Head Office, so store and head-office orders never mix in one push.

Stage 2 (warehouse) — Warehouse selection
  • Only bins with stock on hand greater than 2 are eligible.
  • State priority: NSW / ACT → Sydney first; VIC / TAS / SA / NT → Melbourne first; QLD → Brisbane first.
  • The WA warehouse is not in the automatic rotation.
Stage 3 — Push
  • Stage set to Release To Pick – WMS; invoice date set to today.
  • Saved to Admin, then read back to verify the push actually landed as intended.
Stage 4.5 — Restock sweep

After the main push, a sweep re-checks waiting orders in FIFO order. Only single-item orders are eligible for the sweep, so a restock never half-fills a multi-item order.

Stage 5 — Report

Each round produces a PDF report and an index, and sends a notification — the audit trail for what was pushed, where, and when.

Guardrails — what the automation will never do
  • Runs in DRY-RUN mode for checks before a live push.
  • 3PL setting stays Do Not Transfer to 3PL.
  • Bin stock rule: SOH must be > 2.
  • Passwords are never read or typed by the program; there is no Cin7 API key.
  • If any stage fails, the round stops — it does not skip ahead.

Execution loop

Each round runs the same fixed loop from start (R) to finish (Z), so every round is checked the same way and any failure is easy to locate.
